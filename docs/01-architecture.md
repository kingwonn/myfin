# 01 · 系统架构与演进路线

## 设计哲学：仓库即系统（Repo as System）

传统投研工具把逻辑写死在软件里；本系统把逻辑写在**可被 AI 读写的文本**里：

- **状态** = YAML/Markdown 文件（watchlist、theses、journal）
- **行为** = 技能（`.claude/commands/`）+ 数据管道（`pipelines/`）
- **运行时** = Claude Code（本地或云端会话）
- **调度** = 定时触发（Claude Code Routines / GitHub Actions），实现无人值守的日常扫描

好处：零数据库、零服务器起步；git 天然提供版本、审计与回滚；人和 AI 看到的是同一份真相。

## 三层架构

```
┌─────────────────────────────────────────────────┐
│  L3 决策层（人）                                  │
│  阅读简报 → 评审论点 → 下决策 → 写 journal        │
├─────────────────────────────────────────────────┤
│  L2 研究层（AI 主导，人协作）                      │
│  深度研究 workflow（多路搜索+对抗验证）             │
│  /scan /thesis /brief 技能                       │
│  watchlist ↔ theses ↔ docs/research 知识循环     │
├─────────────────────────────────────────────────┤
│  L1 数据层（管道，渐进建设）                       │
│  行情/财报：OpenBB · akshare/tushare(A股)         │
│  新闻/公告：WebSearch · RSS · 交易所公告           │
│  另类数据：招投标、招聘、供应链调研（后期）           │
└─────────────────────────────────────────────────┘
```

## 演进路线（刻意保持每阶段可用）

### Phase 0 — 骨架（当前）
- 仓库结构、文档、watchlist schema、论点模板、三个核心技能
- 研究靠 Claude Code 会话内的 WebSearch/深度研究 workflow

### Phase 1 — 数据管道最小集
- `pipelines/` 接入 akshare（A股行情/公告）+ OpenBB（美股）
- `/scan` 从"纯搜索"升级为"行情异动 + 新闻扫描"双通道
- 定时任务：每个交易日自动跑 `/brief`

### Phase 2 — 记忆与量化
- 论点与标的的历史表现回测（qlib 或自建轻量回测）
- 事件库：把扫描到的关键事件结构化存储，支持"这个环节过去半年发生了什么"式提问

### Phase 3 — 言出法随完全体
- 任意自然语言研究指令 → 自动分解为 workflow（多 agent 并行）→ 报告落库
- 组合层面的风险监控（集中度、相关性、论点失效预警）

## 关键取舍

| 决策 | 选择 | 理由 |
|------|------|------|
| 存储 | git + 文本文件，不上数据库 | AI 可直接读写；版本审计免费；起步零运维 |
| Agent 框架 | 直接用 Claude Code（技能+workflow），不引入 LangGraph 等 | 我们的编排需求 Claude Code 原生覆盖；少一层抽象 |
| 数据源 | 复用 OpenBB/akshare 等开源 | 自建行情管道是典型的"不值得造的轮子" |
| 回测 | 推迟到 Phase 2 | 当前阶段瓶颈是研究质量，不是回测精度 |
