# myfin — 言出法随 · AI Native 投研系统

> 目标：搭上 AI 算力中心产业链与 Physical AI 产业链的发展轨道，在二级市场获得高倍收益。
> 手段：一个 AI-native 的投研系统，作为持续研究、决策与复盘的基础设施。
> 路径：找到属于我们自己的窄门——高确定性 × 高弹性 × 低拥挤度。

## 什么是"言出法随"

传统投研软件：人适应软件，点菜单、填表格。
本系统：**仓库即系统，语言即接口，Claude Code 即运行时**。

你说"扫一遍光模块产业链最近的产能公告"，系统就去做——因为：

1. **知识库**（`docs/`、`watchlist/`、`theses/`）以结构化 Markdown/YAML 存放，AI 可直接读写；
2. **技能**（`.claude/commands/`）把高频动作固化成一句话可触发的流程；
3. **数据管道**（`pipelines/`）尽量复用成熟开源项目（OpenBB、akshare、qlib 等），必要时造轮子；
4. **每一次研究、每一个论点、每一笔决策都留痕**，可回溯、可证伪、可复盘。

## 仓库结构

```
myfin/
├── README.md                 # 本文件：总览
├── CLAUDE.md                 # AI 运行时的操作手册（Claude Code 每次会话自动加载）
├── docs/
│   ├── 00-vision.md          # 愿景、策略框架、"窄门"定义
│   ├── 01-architecture.md    # 系统三层架构与演进路线
│   ├── 02-tech-stack.md      # 开源选型：站在谁的肩膀上
│   └── research/             # 深度研究报告（带引用、经交叉验证）
├── watchlist/                # 结构化跟踪清单（YAML，机器与人都可读）
│   ├── compute-chain.yaml    # AI 算力中心产业链
│   ├── physical-ai.yaml      # Physical AI 产业链
│   └── private-chokepoints.yaml  # 未上市但卡位咽喉的公司
├── theses/                   # 投资论点：一个论点一个文件，必须可证伪
│   └── TEMPLATE.md
├── journal/                  # 决策与复盘日志（按日期）
└── pipelines/                # 数据管道与工具脚本（渐进式建设）
```

## 工作循环

```
发散研究 → 收敛成论点(thesis) → 挂到 watchlist 持续跟踪 → 触发条件命中 → 决策留痕 → 复盘迭代
```

## 快速开始

在本仓库目录下打开 Claude Code，然后：

- `/scan` — 扫描 watchlist 中标的的最新动态（产能、订单、技术路线变化）
- `/thesis <主题>` — 新建或评审一个投资论点
- `/brief` — 生成一份当前持仓论点 + 关键事件的简报

## 原则

1. **收益是目标，系统是手段**——系统建设永远服务于研究质量，不为了炫技。
2. **只在咽喉处下注**——找产业链上"绕不开"的环节，而不是故事最响的环节。
3. **论点必须可证伪**——写不出"什么情况下我错了"的论点不许进 watchlist。
4. **尽量不造轮子**——优先利用 GitHub 上已被验证的项目；确需自建时果断建。
5. **留痕**——研究、决策、错误全部写下来，复利来自迭代。
